# TIFF sample layout and decoding

Review findings in `internal/cog`'s strip and sample decode paths, each reproduced by a
regression test before fixing.

## Strips

- JPEG-compressed strip TIFFs (GTiff's default for `COMPRESS=JPEG` without `TILED=YES`)
  rendered as noise with no error: the compressed strips were concatenated and read as
  raw samples. Each strip is now decoded as its own JPEG stream (JPEGTables and
  abbreviated streams included), clipped to its rows and stacked; nodata as for JPEG tiles.
- Sparse strips (byte count 0, GDAL `SPARSE_OK`) were skipped, moving every later strip
  of the virtual tile up; the bottom rows became transparent, or 0 m in terrarium. They
  now keep their rows and read as nodata: transparent, NaN, or the GDAL nodata value in
  `ReadUint16Tile`.
- A strip that decodes short (truncated LZW decodes without error up to the damage) is an
  error instead of shifting the strips after it. A tiled source's short tile is an error
  in the RGB path too, as it already was in the float and uint16 paths. Rows past the
  image in the last virtual tile are NaN, not 0, in the float path.
- `RowsPerStrip = 2^32-1` (the spec default, written explicitly) opened with zero tile
  rows and rendered transparent; it now means one strip. A missing or short
  `StripByteCounts`, or a zero width or height, panicked in `Open`; now an error naming
  the file.

## Sample layout

- `ReadUint16Tile` and `decodeRawTile` share one decode (`samples16`): packed, padded
  (9..15 bits in 16-bit words, by tile length) or whole bytes. A padded 12-bit tile
  rendered as garbage; a 17..31-bit tile rendered black; both are now right or an error.
- Signed samples narrower than 16 bits are sign-extended, so -2 no longer sorts above 1
  (rescale, nodata and the value-range scan were wrong for signed 15-bit data).
  `ReadUint16Tile` returns them so that `int16(v)` is the value at every depth, Int8
  included; its format checks run before the read, so an empty tile cannot hide them.
- A predictor on bit-packed samples hung the reader, and planar-separate strips of
  bit-packed samples panicked or misread; both are now an error on the first read.
- Predictor 2 on 64-bit samples (a Float64 DEM) accumulated bytes, not words.
- The no-rescale fallback for 9..16-bit data covers the sample type's range: Int16 was
  mapped from 0..65535 in biased space, so every value <= 0 rendered black.
- Palette images (Photometric 3) are expanded through the ColorMap (tag 320) instead of
  rendering class indices as gray; nodata is an index. WhiteIsZero (Photometric 0 as
  read from the tag) renders inverted; nodata and the rescale use the stored values.
- `ReadUint16Region`: a negative size panicked, and an empty one still read a tile.

## Performance

`decodeRawTile` keeps the byte-aligned per-pixel loop for every depth and rescales
through a table built once per tile. 512x512 tile, min of 15 runs (b300c9e before the
bit-packed patches / 228d2f6 / now): 8-bit gray 307 / 431 / 276 us, 8-bit RGB
1145 / 1319 / 863 us, 16-bit gray 3398 / 3817 / 1337 us, 15-bit packed
- / 2375 / 1067 us. `BenchmarkDecodeRawTile` and a reference case in
`BenchmarkUnpackBits` are new.
