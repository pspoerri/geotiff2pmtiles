# PMTiles reader, header and directory fixes

Review findings in `internal/pmtiles` (reader, header, directory). Regression tests are in
`reader_test.go`, `directory_test.go` and `header_test.go`; each one fails on the old code.

## Reader memory

`OpenReader` expanded every run-length entry into a map slot and a slice element per
addressed tile. A global z0-13 archive (~89M tiles, mostly in long ocean runs) needed about
6 GB before pmtransform did any work. The reader now keeps the sorted run-length entries
unexpanded:

- `ReadTile` binary-searches for the last entry at or before the tile ID and checks the run.
- `TilesAtZoom` clips the runs to that zoom's ID range and allocates its result once, at
  its final size. It returns nil for zooms outside 0-31.
- `NumTiles` is the sum of the run lengths, as before.

`BenchmarkOpenReader`, `BenchmarkReadTile` and `BenchmarkTilesAtZoom` run on a z0-9 archive
(349,525 tiles, three quarters in ocean runs). Times were measured on a busy machine, so
only their rough size means anything:

| Benchmark     | Before                          | After                          |
|---------------|---------------------------------|--------------------------------|
| OpenReader    | ~20 ms, 79.3 MB/op, 2,082 allocs | ~2-3 ms, 15.1 MB/op, ~600 allocs |
| ReadTile      | ~390 ns                         | ~350 ns                        |
| TilesAtZoom   | ~8 ms, 35.4 MB/op, 32 allocs    | ~6 ms, 6.3 MB/op, 1 alloc      |

## Internal compression and nested leaves

The reader gunzipped directories and metadata whatever `InternalCompression` said. An
archive with uncompressed directories is valid and go-pmtiles accepts it, but here it
failed with `gzip: invalid header`. Directories and metadata are now decompressed as the
header says: none, gzip, or unknown (read as none, as the reference JS reader does). Any
other value fails with `unsupported internal compression N`. Brotli and zstd directories
are not read; go-pmtiles does not read them either.

Leaf pointers were followed from the root only, so a leaf nested in a leaf was silently
dropped along with all its tiles. They are now followed to any depth. A directory that is
referenced twice (a cycle in a corrupt archive) is an error instead of endless recursion.

`DeserializeDirectoryCompressed(data, compression)` exposes this to the CLI tools.
`DeserializeDirectory` stays gzip-only.

## TileIDToZXY

The zoom search computed 4^z as `n*n`, which overflows from z=32 on, so any ID at or
beyond (4^32-1)/3 looped forever. The search now stops at z=31 and returns z = -1 for IDs
past it.

## Tile types

Added `TileTypeAVIF` (5) and `TileTypeMLT` (6). `TileTypeString` names them `avif` and
`mlt`.

## Header bounds precision

The bounds and center passed through float32 before E7 encoding. The largest error is
7.6e-6 degrees, about 0.85 m, and it could leave the bbox slightly inside the data (e.g.
-45.1234567 was written as -45.1234550). A header read and written back (pmheader patching
the zoom) also shifted its bounds.

`Header` now keeps the exact E7 values in an unexported field set by `NewHeader` and
`DeserializeHeader`. `Serialize` uses them for every float32 field the caller has not
changed, so the exported field types are unchanged. `NewHeader` rounds minimums down and
maximums up, so the bbox contains the data. It first snaps float noise, so 45.82 stays
45.82. `Header.Bounds()` returns the exact bounds as float64.

`TestHeaderSerialize_Bounds` tolerance tightened from 1e-4 to 1e-7 degrees.
