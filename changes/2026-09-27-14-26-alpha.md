# Straight alpha end to end, alpha-weighted downsampling

## Convention

Pipeline `*image.RGBA` buffers hold straight (non-premultiplied) alpha. The samplers
in `resample.go` and the COG reader already produced it; the encoders and decoders
treated the same buffers as Go's premultiplied `*image.RGBA`.

## Fixes

- **Encoders** (`internal/encode`): `image/png` and the pure-Go WebP encoder
  (nativewebp) un-premultiplied straight pixels a second time, so 200,100,50,128 was
  stored as 143,199,99,128 (R wrapped, G/B doubled). Every semi-transparent pixel of PNG
  output and of WebP from `CGO_ENABLED=0` builds was wrong: nodata edges with
  bilinear/bicubic/lanczos, and every pixel with `--alpha-band`. PNG, Terrarium and
  pure-Go WebP now get a zero-copy `*image.NRGBA` view of the same `Pix` (`asNRGBA`).
  CGo WebP (`WebPEncodeRGBA` takes straight RGBA) and JPEG (no alpha) were already
  right for `*image.RGBA`. JPEG now also converts any other image type to straight
  RGB. Without that, the `TileData.At` change below would composite a
  semi-transparent uniform tile onto black.
- **Decoder** (`encode.DecodeImage`): PNG and pure-Go WebP return `*image.NRGBA`
  (or `Paletted`/`NRGBA64`/`NYCbCrA`), which the disk store and `pmtransform` drew
  into `*image.RGBA`, premultiplying it. Images with alpha now come back as straight
  `*image.RGBA` (zero-copy for NRGBA); opaque images keep their decoder type. The
  store read 200,100,50,128 back as 72,100,49,128 before.
- **TileData** reports its colours as `color.NRGBA` (`ColorModel` is `NRGBAModel`), so
  encoders reading a uniform tile through `At` see straight colours: a
  `--fill-color 255,0,0,128` PNG tile was stored as 253,0,0,128.
- **Downsampling** (`downsample.go`): RGB was averaged over every pixel with non-zero
  alpha at full weight, so an alpha-1 edge pixel pulled as hard as an opaque one
  (opaque red beside alpha-1 blue became purple). Bilinear, bicubic and Lanczos now
  weight RGB by alpha; opaque data gives the same result, and a pixel whose alpha
  rounds to 0 stays transparent black. Gray, uniform, nearest, mode and Terrarium paths
  are unchanged.
- Removed dead code: `TileData.SerializeAppend`, `DeserializeTileData`, the
  `tileDataType` tags and `TileData.MemoryBytes`, with their tests and benchmarks. The
  disk store keeps encoded tile bytes, so this "disk spilling" format was never used.

Regression tests: `internal/encode/alpha_test.go`, `internal/tile/alpha_test.go`.

## Not fixed

The 2x pyramid kernels are not stretched by the scale factor, so bicubic/Lanczos
overviews alias more than bilinear (box). Stretched 8/12-tap kernels reach up to 5 px
into neighbouring child tiles. Each child quadrant is downsampled on its own, with
out-of-tile taps counted as transparent, so alpha would drop to ~240 along every tile
seam (~225 at corners). A correct fix has to read across child tiles.
