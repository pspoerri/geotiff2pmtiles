# Auto rescale range, nodata flood mask and tile caches

Review fixes in `internal/cog` (value range, flood mask, tile caches).

## Auto rescale range (`ValueRange`)

- `ValueRange(cfg BandConfig)` now covers only the bands that are rendered: the R, G, B
  bands of `cfg` (defaults 1,2,3; band 1 for single-band data), without duplicates, never
  the alpha band and never bands the file lacks. It used to take the min/max over every
  band, so a bright NIR band (4-band B,G,R,NIR without descriptions, even with the default
  `--bands 1,2,3`) or a 0/65535 alpha band stretched the range and the RGB came out dark.
  GDAL `STATISTICS_*` are used only when every rendered band has them; a partial set would
  clip the band without statistics, so the pixels are scanned instead.
- The pixel scan picks its (up to 64) tiles on a grid over both axes (`scanGrid`). The old
  stride through the row-major tile index aliased with the tile columns: 64×64 tiles gave a
  stride of 64 and only column 0 was read, so a nodata western border made auto-rescale
  fail and anything else gave the range of one strip.
- `ErrNoValueRange` is returned when every sampled pixel is nodata, so a caller merging
  several sources can tell an all-ocean source apart from a read error.
- CLI: `resolveRescaleRange` passes the band config to `ValueRange`.

## Nodata flood mask (`BuildFloodMask`)

- Pass 1 matched nodata on the decoded RGB with `HasNodata` switched off. The decode then
  fell back to the file's `GDAL_NODATA` tag and zeroed exact-nodata pixels, so with a
  non-zero tag (a white 255 border) they no longer matched and `--nodata-flood` left the
  border opaque, worse than without the flag. For 9-16 bit input the RGB was also rescaled
  to 8 bits while nodata and tolerance stayed raw, so e.g. 65535 never matched.
- Uncompressed, LZW, Deflate and ZSTD sources are now matched on their stored samples
  (`ReadUint16Tile`), in the same signed-biased space as the decode: a pixel is a
  candidate when every rendered band is within tolerance of nodata, or when its alpha
  sample is 0 (so the flood still passes through transparent pixels whatever RGB they
  carry). JPEG keeps matching the decoded RGB; it has no tag fallback and was not affected.
