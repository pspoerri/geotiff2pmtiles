# Sampling geometry, georeferencing, per-source projection

Review findings for the global satellite composite; each reproduced by a test before fixing.

## Placement

- Half-pixel shift: the samplers treat integer coordinates as pixel centres, but the
  dispatchers passed corner-based coordinates (`(x - OriginX) / pixelSize`). Every raster
  was drawn half a source pixel north-west, measured at the overview level in use (~225 m
  for GEBCO at native zoom, more from overviews). Both dispatchers now subtract 0.5 once,
  after the bounds check; the sampler clamps handle the edge half-pixel.
- `GTRasterTypeGeoKey` (1025) is read. For `RasterPixelIsPoint` (Copernicus DEM, SRTM)
  the tiepoint is a pixel centre and the origin moves half a pixel up-left, as in GDAL.
  These files were accidentally right before (the two errors cancelled); now both
  conventions land where GDAL puts them. `coginfo` prints the corner origin for them.
- Test: `TestFeatureLandsAtGDALPosition`: a one-pixel feature, Area and Point, two zooms,
  all five resampling modes, RGB and float, within 0.05 output px.

## Float kernels next to nodata

- With the shift, grid-aligned sources sample at integer offsets. The float Lanczos and
  bicubic samplers renormalise by the weight of the valid taps; when those sit at kernel
  zeros next to nodata the sum is ~1e-6 and the result a spike (-52 m, 1502 m). A valid
  weight below 0.25 now falls back to the nearest pixel, as when every tap is nodata.
- The Lanczos and bicubic tables include the zero at the support edge; the last entry
  (~1e-6) was returned for the whole final interval.
- Tests: `TestFloatKernelsNearNodataEdge`, `TestKernelLUTTapersToSupportEdge`.

## CRS

- `parseEPSG` follows `GTModelTypeGeoKey`. It returned the first key in directory order,
  so `GeographicTypeGeoKey` won over `ProjectedCSTypeGeoKey`; GDAL writes
  `GeographicType=<datum>` next to `ProjectedCSType=32767` for custom Albers/LCC, and those
  metres were read as degrees. A user-defined CRS is now reported as 32767 and fails in
  `tile.Generate` with a message naming the file. Test: `TestParseEPSG`.
- Each source is reprojected with its own CRS (one `Projection` per EPSG code). All
  sources used `sources[0]`'s CRS, so e.g. Sentinel-2 tiles from UTM 32N and 33N were
  dropped or misplaced. The tile's CRS box and pixel size are computed per distinct
  projection; a pixel is projected again only when the next source's CRS differs, so
  single-CRS input costs the same as before. Source infos are built once in `Generate`.
  Tests: `TestMixedCRSSourcesLandInPlace`, `TestBuildSourceInfosRejectsUnknownCRS`.

## Other

- `tile.Config.FloatNodata` overrides every source's `GDAL_NODATA` in the terrarium path
  (any float, rounded to float32 like the tag). Nodata output stays RGBA 0,0,0,0.
  Test: `TestGenerateTerrariumFloatNodata` (a -9999 void without the tag).
- The Lanczos/bicubic YCbCr fast paths run only for 4:4:4, 4:2:2 and 4:2:0 tiles. 4:4:0,
  4:1:1 and 4:1:0 JPEG tiles got wrong colours and then an index-out-of-range panic that
  crashed the run; they now take the generic path. Test:
  `TestYCbCrFastPathsAllSubsampleRatios`.
