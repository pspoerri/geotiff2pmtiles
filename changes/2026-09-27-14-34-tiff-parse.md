# TIFF parsing, overview selection, EPSG and ByteSource fixes

Review findings in `internal/cog` (IFD parsing, sources, georeferencing inputs), each with a
regression test that failed before the fix.

## Malformed files

- An IFD chain pointing back at itself looped forever while memory grew. The chain now
  stops with an error on a repeated offset, or after 65536 IFDs.
- A garbage BigTIFF entry count (e.g. 2^60) or tag count (e.g. 2^61 LONG8 values, whose
  byte size wrapped to 0 and passed as inline) panicked in `make`. Entry counts are capped
  at 65536 and tag data is checked against the file size before it is allocated.
- The value getters ignored the declared type: a BYTE `BitsPerSample` was read as SHORT past
  its 4-byte value, a LONG8 value with count 0 in a classic TIFF read 8 bytes of 4. They now
  dispatch on the type and never read past the value bytes.
- A 0-pixel image divided by zero during strip promotion; it is now an open error.
- `dataTypeSize` gives IFD8 8 bytes (was 4) and IFD 4 bytes (was 1).

Every such file now fails with `parsing <file>: ...` instead of a panic or hang.

## Overview levels

Every IFD in the chain used to become a level. A GDAL COG with an internal mask ends its chain
with the smallest overview's 1-bit mask, so auto rescale (`ValueRange`) failed with "pixel scan
supports only 9..16-bit data"; a striped reduced-resolution IFD divided by zero once
`OverviewForZoom` picked it. `OpenSource` now keeps IFD 0 plus the IFDs that can be its
overviews: not a mask (NewSubfileType bit 4 or Photometric 4) or page (bit 2), tiled, no
larger than IFD 0, same samples per pixel and depth, supported compression. The
reduced-resolution bit is not required, since some writers omit tag 254. `IFDCount` and
`NumOverviews` no longer count masks (coginfo on a masked COG: 4 levels, was 8). Masks are
dropped, not applied.

## EPSG

- A TIFF with GeoKeys but no pixel-grid tags plus a `.tfw` lost its GeoKeys EPSG: the world
  file replaced the whole GeoInfo and the coordinate-range guess made a UTM 32N file Web
  Mercator. The world file now only supplies the grid.
- A guessed EPSG is logged: `WARNING: <file> has no CRS in its GeoTIFF keys; guessed
  EPSG:3857 from the coordinate ranges. ...`.
- `Reader.SetEPSG` overrides the CRS (call before the reader is shared).

## ByteSource and Reader lifecycle

- Reads after `Close` panicked on a nil source; `Close` now installs a `closedSource` whose
  reads return `cog: reader is closed`. A second `Close` does nothing.
- Four copies of `end := offset + size; if end > Size()` were not overflow-safe (a BigTIFF
  offset near 2^64 wrapped and handed the source an inverted range). One `Reader.slice`
  helper now checks `offset > n || size > n-offset` before `Slice`, so a ByteSource only ever
  sees `0 <= off <= end <= Size()`.
- `RawBytes` panicked for an offset past the end and returned zeros on a read error; it
  returns nil for both.
- Reader IDs come from a process-wide atomic counter. `OpenAll` used 0..n-1 and every other
  reader had 0, so readers from `Open`/`OpenSource` or a second `OpenAll` shared tile cache
  keys. `SetID` remains as an optional override.
- `sourceReadSeeker` fetches 64 KiB read-ahead blocks: opening a COG took one `Slice` per
  directory entry (~150 for a 6-IFD COG, a round trip each over HTTP); now one.
- Docs: `ByteSource` states the range contract and that `Slice` results are only valid until
  `Close`; `OpenSource` takes ownership of `src` (closed on error and by `Reader.Close`); stale
  "memory-mapped" comments reworded.

## Tests

`internal/cog/parse_test.go` (crafted malformed files, IFD selection, GDAL mask order),
`tfw_test.go` (EPSG with a world file, guess warning, `SetEPSG`), `source_test.go`
(`OpenSource` over a plain byte source, read after `Close`, out-of-range tile/strip/planar
ranges against a naive source, `RawBytes`, unique IDs, `sourceReadSeeker` vs `bytes.Reader`,
`Slice` call count, source ownership), with a small TIFF builder in `tiffbuild_test.go`.
Hand-built test readers use a plain `bytesSource` instead of wrapping heap memory in
`mmapSource`.
