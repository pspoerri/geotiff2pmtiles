# Pipeline robustness: spilling, cancellation, writer

Review findings for long global runs; each has a regression test that failed before the fix.

## Disk tile store (`internal/tile/diskstore.go`)

- Lost wakeup: the I/O goroutine released spilled bytes and broadcast without holding
  `spillMu`, the lock `Put` waits under. A broadcast between a waiter's check and its
  `Wait` was lost, and at the end of a level nothing broadcast again: the worker stayed
  parked at 0% CPU (small `--mem-limit`, or 1024 px tiles). The release now happens under
  `spillMu`. `TestDiskTileStore_BackpressureNoDeadlock` (64 producers, 1-byte limit) hung
  in about one run in five before.
- I/O errors: spill write errors were only logged (a short write shifted every later
  offset), and read-back or decode errors made `Get` return nil, which the pyramid treats
  as a missing tile, so lower zooms got silent holes. The store now records its first
  error; `Err`, `Put` and `Drain` return it, and `Get` records failures with the tile's
  z/x/y. After an error the I/O goroutine stops writing but keeps releasing bytes, so no
  `Put` waits forever. `Generate` and `Transform` fail the level on it.

## Generate / Transform workers

- A worker error only stopped that worker; the others finished the level (8160 more
  tiles in the verifier's rebuild), and once all workers had returned the batch producer
  blocked forever. Each level now runs under `context.WithCancelCause`: the first error
  cancels it, workers stop at their next tile, the producer selects on `ctx.Done`.
- `defer store.Close()` bound the initial placeholder store, so an error below max zoom
  left the previous level's spill file (the largest one) behind. It is now a closure.

## PMTiles writer (`internal/pmtiles/writer.go`)

- `Finalize` truncated the output with `os.Create` before copying any data and ignored
  the close error, so a failed re-run destroyed the previous archive. It now writes
  `<output>.partial` next to the output (created like `os.Create`, so the archive keeps
  the usual permissions), syncs, checks `Close`, and renames it over the output only on
  success; any failure removes the partial file and the temp tile file.
- The clustered temp copy is gone: new offsets are assigned in memory and each unique
  tile is streamed from the temp file straight into the archive. A synthetic run
  (58 MB archive) wrote 4.0x the archive size before and 3.0x now; peak disk stays 2.0x.
- Dedup compared only the FNV-64a hash and length; a hit now reads the candidate back
  and compares bytes. Only tiles up to tileSize²/16 bytes (4 KiB at 256 px, 64 KiB at
  1024 px; uniform tiles are far smaller) are hashed and remembered, which bounds the
  dedup map and the clustering map. The dedup map is freed before clustering.
- `Abort` is idempotent, and `WriteTile` after `Finalize`/`Abort` returns an error.

## Memory limit (`internal/tile/memlimit.go`, `sysinfo_linux.go`)

- Auto returned 0 (spilling off, every tile of a level in RAM) when the formula came
  out under 512 MB, i.e. below about 2.85 GB of RAM, or when RAM detection failed. It is
  now never below 256 MB. On Linux the cgroup v2 `memory.max` (or v1
  `memory.limit_in_bytes`) caps the RAM figure, so containers no longer see host RAM.
  The sysinfo product is computed in uint64, which fixes the build on 32-bit Linux.

## Progress (`internal/tile/progress.go`)

- When stderr is not a terminal, the bar prints only its final state, one line per zoom
  level, instead of a `\r` frame every 100 ms (~36k frames an hour in a log file).
  `Finish` waits for the refresh goroutine, so no redraw follows the final line.

## Not changed

- Unlinking temp files right after creation (to free space after SIGKILL or an OOM
  kill) was evaluated and left out; see DESIGN notes in the review hand-off.
- The store still writes every tile a second time (its own spill file next to the
  writer's temp file); removing that needs a `TileWriter` interface change.
